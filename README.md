# Syntrix ServiceOps

منصة عربية لإدارة شركات الصيانة والخدمات الميدانية، من طلب العميل وتعيين الفني حتى التقرير الصوتي ومراجعته واعتماده ومشاركته مع العميل. الواجهة تدعم العربية RTL وتعمل كتطبيق PWA قابل للتثبيت من المتصفح على الهاتف.

## الوظائف الأساسية
- إدارة الشركات والمستخدمين والعملاء وطلبات الصيانة.
- مساحة فني مبسطة بثلاثة أقسام: مهام اليوم، تسجيل تقرير صوتي، وتقاريري.
- تسجيل صوت مباشر من الهاتف وحفظ الملف الأصلي، مع إرفاق الصور.
- تحويل الصوت إلى نص عربي/مصري وإنشاء مسودة تقرير قابلة للتعديل عند ضبط `OPENAI_API_KEY`.
- فصل صلاحيات الفني عن المدير: الفني يعدّل تقاريره ويرسلها للمراجعة؛ المدير يراجع ويعدّل ويعتمد ويصدر رابط العميل.
- تقارير باسم الفني، وسجل للتقارير والطلبات حتى بعد حذف حساب الفني.
- إدارة العملاء وأعضاء الفريق وطلبات الصيانة والتقارير من لوحة المدير.
- إعدادات الشركة وعروض الأسعار والفواتير والعقود والتذكيرات.
- صفحات تقارير عامة لا تعرض التقرير للعميل إلا بعد الاعتماد.
- هوية المنتج: `Syntrix ServiceOps` و`A Syntrix Product`.
- ملفات PWA والأيقونات وService Worker لدعم الإضافة إلى الشاشة الرئيسية.

## الأدوار
- **مالك الشركة / المدير:** إدارة بيانات الشركة والعملاء والفريق والطلبات والتقارير، ومراجعة التقارير واعتمادها.
- **الفني:** يرى المهام المسندة إليه فقط، ويسجّل تقاريره ويتابع حالتها. لا يستطيع اعتماد تقاريره أو الوصول إلى بيانات باقي الشركة.
- **مدير المنصة:** أدوات إدارة المنصة المنفصلة.

حذف الفني يزيل حساب الدخول، لكن سجلات الزيارات والطلبات القديمة تبقى محفوظة. حذف تقرير يزيل التقرير وملفاته المرتبطة. لا يُحذف طلب صيانة مرتبط بتقرير زيارة حتى لا تضيع سلسلة السجل.

## المتطلبات
- Node.js 22 أو أحدث.
- قاعدة PostgreSQL؛ في هذا المشروع تم استخدام Supabase.
- مفتاح OpenAI API اختياري للتفريغ الصوتي وإنشاء التقرير تلقائيًا.

## التشغيل على Windows مع قاعدة Supabase الحالية
1. احتفظ بملف `.env` الحالي الذي يحتوي على إعداد اتصال Supabase. لا تستبدله بقيم تجريبية.
2. يجب أن يحتوي ملف `.env` على `DATABASE_URL` الصحيح، و`PGSSL=true`. عند الحاجة لشهادة Supabase CA الرسمية، اضبط `PGSSL_CA_FILE=certs/supabase-ca.crt`.
3. شغّل `START-WINDOWS.bat` أو نفّذ `npm install` مرة واحدة ثم `npm run dev`.
4. افتح `http://localhost:5173`.

**لا تشغّل `npm run db:seed` على قاعدة بياناتك الحالية.** الأمر مخصص لقاعدة اختبار فارغة، وقد ينشئ حسابات وبيانات تجريبية. لا تستخدم `supabase db reset`.

## إعداد تحويل الصوت
أضف المفتاح في `.env` محليًا أو في Environment داخل خدمة الاستضافة:

```env
OPENAI_API_KEY=your_secret_key
OPENAI_TRANSCRIBE_MODEL=gpt-4o-mini-transcribe
OPENAI_REPORT_MODEL=gpt-4o-mini
```

يُحفظ التسجيل الأصلي قبل التحويل. يطلب النظام من نموذج التقرير عدم اختراع قياسات أو قطع غيار أو سبب عطل، ووضع المعلومات غير المذكورة ضمن قائمة منفصلة للمراجعة.

## النشر على Render مع Supabase
استخدم الدليل `DEPLOY-RENDER-AR.md`. الإعداد لا ينشئ قاعدة Render جديدة ولا ينفذ seed تلقائيًا؛ أدخل رابط Session Pooler الخاص بقاعدة Supabase الحالية كمتغير `DATABASE_URL` في Render.

## قاعدة البيانات والاشتراكات
تبقى جداول الباقات والاشتراكات والمدفوعات موجودة في قاعدة البيانات للتوسع المستقبلي، لكن صفحات الباقات وقيودها التشغيلية متوقفة في هذه النسخة. لا يتطلب هذا التغيير حذف جداول أو بيانات موجودة.

## ملاحظات إنتاجية
- لا ترفع `.env` أو كلمات المرور أو مفاتيح API إلى GitHub.
- استخدم HTTPS؛ الميكروفون يحتاج اتصالًا آمنًا.
- احتفظ بقرص دائم للتسجيلات والصور، واختبر النسخ الاحتياطية قبل استقبال بيانات العملاء.
- هذه نسخة PWA يمكن تثبيتها من المتصفح، وليست تطبيق متجر أصليًا.
